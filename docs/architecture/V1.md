## 1. Mission

A single-machine, strategy-agnostic quantitative research platform in which a
research idea normally requires only plugin implementation(s), an experiment
configuration, and tests — never changes to data, simulation, evaluation,
experiment tracking, or infrastructure layers. Every result is reproducible,
leak-audited, and comparable.

**Strategy-agnostic principle.** The platform is not designed around vector
similarity, XAUUSD, M1, MetaTrader 5, one model family, one decision format,
or one execution model. The first planned research plugin (similarity search
over historical observations) is ResearchModel implementation #1 — nothing
more. Rule-based, statistical, ML, regime, price-action, window-free, and
representation-free approaches must run through identical contracts. If a
plugin needs an infrastructure change, that is an architecture finding, not a
patch ([ADR-0006](../adr/ADR-0006-fixed-stage-pipeline.md)).

## 2. High-level architecture

```
┌──────────────────────── EXPERIMENTS (composition root) ────────────────────────┐
│ config schema · resolver · orchestrator · CLI · detached execution · registry  │
└──────────────┬──────────────────────────┬──────────────────────────┬───────────┘
               │                          │                          │
       ┌───────▼───────┐        ┌─────────▼──────────┐      ┌────────▼─────────┐
       │  DATA LAYER   │        │  RESEARCH STAGES   │      │   MEASUREMENT    │
       │ dataset       │ frames │ features → repr →  │frames│ plane A:         │
       │ registry ·    ├───────▶│ fit → infer →      ├─────▶│ forecast eval    │
       │ integrity ·   │ views  │ ModelOutputFrame → │      │ (OutcomeSpec)    │
       │ MarketFrame · │        │ policies →         │      │ plane B: sim →   │
       │ GapIndex ·    │        │ IntentFrames       │      │ trade eval       │
       │ split/lockbox │        │                    │      │ (ADR-0020 status)│
       └───────────────┘        └────────────────────┘      └──────────────────┘
               └──────────── ARTIFACT STORE + MaterializationPolicy ────────────┘
```

**Stable infrastructure boundaries:** core contracts and identity, time model,
data layer, artifact store, orchestrator/CLI/registry, evaluation harnesses,
simulator engine, test rigs.

**Replaceable plugin boundaries:** FeatureProvider, RepresentationModel,
ResearchModel, DecisionPolicy, IntentFrame schemas, OutcomeSpec, Evaluator
metric sets, ExecutionSpec presets, dataset adapters, sweep generators.

**Dependency direction** (enforced by architecture tests):

```
core ← {data, features, representations, models, decisions,
        outcomes, simulation, evaluation, artifacts} ← experiments
```

**Prohibited dependencies:**
- `core` imports nothing internal.
- Research layers never import each other; composition happens only in
  `experiments`.
- Plugins never import other plugins' modules; sharing goes through core
  contracts.
- `simulation` and `evaluation` consume artifacts/frames only — they import
  `core` and nothing else, so `models`, `decisions`, `features`,
  `representations`, `outcomes`, `artifacts` and `data` are all out of reach.
  `GapIndex` therefore cannot enter the simulator, and does not need to:
  execution happens only at observed rows, so a bar that does not exist is not
  a fill opportunity
  ([ADR-0023](../adr/ADR-0023-phase-4-simulation-contracts.md) §9).
- No pandas/Polars/DuckDB types in public contract signatures (internal use
  inside a plugin is fine).
- Nothing outside `experiments` touches the registry index or run
  directories.

## 3. Time model ([ADR-0002](../adr/ADR-0002-native-time-model.md))

**NativeTimeKey** = `{value: int64, unit, clock_domain}`. Frames carry a bare
int64 index plus one frame-level `(unit, clock_domain)` tag — never per-row
key objects. The current dataset's domain is
`mt5.justmarkets-demo3.wallclock` (unit: seconds); the field name
`mt5_time_raw` exists only inside the MT5 dataset adapter.

**The no-UTC rule.** The dataset encodes broker wall-clock through the epoch
convention. It is NOT UTC and nothing in the platform may claim, attach, or
"correct" toward UTC. The invariant is **no untagged time**, not
"everything must be UTC".

- Cross-clock-domain comparison or joining is a refusal; no resolver exists
  in V1.
- Calendar/time-of-day logic requires an explicit CalendarTimePolicy. V1
  ships exactly one: `native-wallclock-v1` (mechanical decode, treated as
  broker wall-clock civil time, valid only inside this domain). Split
  boundaries use this same policy.
- Works without any resolution: ordering, PIT slicing, observed-bar windows,
  fitting, inference, decision alignment, bar-unit evaluation, simulation.
- Blocked until a real resolver exists: UTC mapping, external time-based
  feeds (economic calendars, news), cross-domain studies.

## 4. Data and view model

**MarketFrame** ([ADR-0003](../adr/ADR-0003-columnar-hot-path.md)) is a
deliberately **small** public abstraction: native-key index, typed named
columns, schema metadata, ClockDomain, DatasetRef, and bounded/PIT views.
It is not — and must not grow into — a general-purpose DataFrame library.
NumPy/Arrow or similar are implementation details behind it. A view's upper
bound IS the point-in-time boundary. Domain objects (per-row types) survive
only at validation boundaries, in tests, and as documentation vocabulary —
never as the bulk carrier.

**DatasetRef** carries `dataset_id`, `manifest_sha256`, and `role`
([ADR-0004](../adr/ADR-0004-dataset-admission-and-integrity.md)); its
**canonical identity is `(dataset_id, manifest_sha256)`** — `role` is a
validated field that must agree with the role the referenced manifest
declares, not an independent third component (changing role changes the
manifest, and therefore already changes `manifest_sha256`). The curated
manifest is the sole admission authority — directory globbing is prohibited
and tested. Integrity policy `full` (hash every referenced file before first
Parquet decode) is required for canonical runs; any mismatch is a hard
refusal. Partition pruning applies only to Parquet decoding and array
materialization: all target-referenced files are still integrity-hashed. A
partition source supplies location only and never overrides the target
manifest's admission metadata.

The sole public market-row loading authority is the process-local
`AccessGrant` issued by the gate. The loader independently resolves the
grant's exact target and current split policy, calls `require_matches()`
immediately before its first partition-file access, and exposes no bare-ref,
manifest, path, or bypass route. RAW remains a registered provenance and
partition-source identity but is not a legal public `MarketFrame` target in
V1; public frames come from CURATED or generated v1.1 views.

**GapIndex** ([ADR-0005](../adr/ADR-0005-gapindex-not-sessionmodel.md))
records arithmetic continuity facts only: deltas, nominal-interval deviation,
objectively known boundaries. It never claims a session, holiday, outage, or
closure. A market-closure claim anywhere in V1 is a bug by definition.

**Splits and lockbox**
([ADR-0012](../adr/ADR-0012-two-tier-splits.md),
[ADR-0013](../adr/ADR-0013-lockbox-enforcement.md),
[ADR-0014](../adr/ADR-0014-snapshot-and-view-roles.md)):

| Identity / view role | Range (native-wallclock-v1) | Default discovery |
|---|---|---|
| RAW parent dataset | full raw range (extends past OOS) | **no** — gated ceremony |
| CURATED parent dataset | first usable bar → live edge (extends past OOS) | **no** — gated ceremony |
| SNAPSHOT (parent anchor) | first usable bar → last bar ≤ 2026-07-31 | **no** — gated (AO-1) |
| TRAIN | 2020-01-01 → 2023-12-31 | yes |
| VALIDATION | 2024-01-01 → 2024-12-31 | yes |
| OOS | 2025-01-01 → 2025-12-31 | **no** — explicit access, audited from Phase 1 |
| LOCKBOX | 2026-01-01 → snapshot boundary | **no** — unlock ceremony |

**Normative split dates: [ADR-0012](../adr/ADR-0012-two-tier-splits.md).**
The table above summarizes; where it differs, ADR-0012 governs.
[RESEARCH_POLICY.md](../research/RESEARCH_POLICY.md) explains the reasoning
in plain language. These dates are V1 **research policy**, never hardcoded
platform assumptions.

**Gating is derived from range, not from names**
([ADR-0014](../adr/ADR-0014-snapshot-and-view-roles.md) Amendment 1): any
DatasetRef or view whose admitted native range extends **beyond the OOS
upper boundary** is `discovery_default: false`, unreachable through normal
role resolution, and protected by the full ADR-0013 ceremony. That covers
the raw and curated parents as well as SNAPSHOT and LOCKBOX — a config
cannot bypass the lockbox by naming a parent identity directly.

- **AO-1 resolution (ratified):** the full snapshot contains lockbox rows,
  so it is an identity anchor/parent only — gated exactly like the lockbox,
  `discovery_default=false`.
- **AO-2 resolution (ratified):** Tier-1 integrity boundaries are
  materialized, hash-pinned curated views. Tier-2 procedural folds
  (walk-forward ranges etc.) are runtime-generated, must lie fully inside
  one Tier-1 view (runtime-checked), and are recorded in the RunManifest.
- **Fold-boundary purge (ADR-0012 Amendment 1):** every training sample has
  an information span `[context_start … decision_key … target_end]` derived
  from declared feature lookback and the declared training OutcomeSpec. No
  sample whose span overlaps the evaluation range may remain in the fit set.
  The platform derives the minimum purge from those declarations, applies it
  automatically, records it in the RunManifest, and permits reduction only
  with an explicit recorded reason. Optional embargo is additive.
- **View composition (ADR-0012 Amendment 2):** a bounded evaluation view is
  `(context_start, eval_start, eval_end)`. Predictions and metrics belong
  only to `[eval_start, eval_end]`; `eval_end` is the point-in-time upper
  boundary. Backward context may reach before `eval_start` into strictly
  **earlier authorized** views — never a later view, never a gated view
  without authorization. A **fit** input may be a recorded ordered union of
  **adjacent, non-gated** Tier-1 views (TRAIN; TRAIN+VALIDATION after a
  promotion decision; +OOS only where policy permits and access is
  recorded), each member pinned by id and manifest hash. Hand-written date
  ranges are never a substitute.
- **Owner amendment (ratified):** default research discovery exposes TRAIN
  and VALIDATION only. OOS access is easier than lockbox access but must be
  explicit and is permanently recorded (`oos_touched`).
- **Lockbox ceremony:** explicit CLI unlock flag + structured reason in the
  resolved config + write-ahead audit event before any data is returned +
  permanent `lockbox_touched` marking. No agent filesystem hook in V1
  unless separately approved.

## 5. Stage model and artifacts

Fixed-stage pipeline ([ADR-0006](../adr/ADR-0006-fixed-stage-pipeline.md)) —
no DAG engine, no fused call, no microservices. Windowing is a plugin-declared
WindowSpec, not a global stage; window-free models pay nothing for it.

Every stage is a pure, deterministic function of (declared inputs, identity,
seed). Two hashes with distinct jobs
([ADR-0007](../adr/ADR-0007-materialization-policy.md)):
- **Identity key** — computed before execution from input identities +
  plugin id/version/params + code hash + **platform-code identity (repo Git
  commit, plus diff identity for noncanonical runs)** + seed. Always
  computed; is the cache key; a key mismatch IS invalidation (immutable
  entries, no TTL). A core alignment or frame fix therefore invalidates old
  caches — deliberately.
- **Content hash** — SHA256 of canonical serialized output; computed on
  materialization or in determinism-verification mode.
- **Determinism verification bypasses cache reads** and recomputes every
  stage; it must never compare a cached artifact with itself
  ([ADR-0016](../adr/ADR-0016-determinism-tiers.md)).

**MaterializationPolicy:** `ephemeral` · `cache_if_expensive` (V1: driven by
an explicit plugin/stage cost hint, not a measured wall-time threshold) ·
`persist` · `persist_on_failure`. Manifests, resolved configs, metrics,
identity blocks, audit events, and failure records are always persisted
regardless of policy. ModelOutputFrame defaults to `persist` (multi-policy
fan-out point); TradeLog and EquityCurve likewise `persist`, and IntentFrame
is `ephemeral` **until simulation is configured**, at which point the
orchestrator's downstream-consumer upgrade makes it durable. Artifact writes
are atomic (temp file + rename); the audit log is append-only
([ADR-0017](../adr/ADR-0017-storage-files-as-truth.md)).

## 6. Research contracts

**Fit lifecycle** ([ADR-0008](../adr/ADR-0008-fit-lifecycle-and-fittedstate.md),
[ADR-0022 Amendment 3](../adr/ADR-0022-phase-3-research-contracts.md)):
`fit(train_view, inputs, training_targets=None) → FittedPayload`; the
orchestrator binds the complete identity to mint `FittedState`;
`infer(eval_view, fitted_state, inputs) → ModelOutputFrame`. Stateless models
implement no-op fit. RepresentationModel participates in the same lifecycle
(a scaler or PCA is fitted state). **FittedState identity pins:** model id +
params, training DatasetRef/view range, feature/representation identities,
training OutcomeSpec id/params/target range/alignment, applied purge, code
identity, dependency identity, seed. No fitted model may hide what data it
saw.

**Training targets — the one fit-time forward channel**
([ADR-0010](../adr/ADR-0010-two-plane-evaluation-and-outcomespec.md)):

```
training view → config-declared OutcomeSpec → orchestrator builds
TrainingTargetFrame → ResearchModel.fit(inputs, training_targets) → FittedPayload
→ orchestrator binds complete identity → FittedState
```

The reserved outcome namespace remains **prohibited** as feature input,
inference input, and DecisionPolicy input. Supervised and statistical
fitting consume targets only through this platform-controlled channel: the
config names the OutcomeSpec explicitly, the **orchestrator** (never the
model) computes it, targets stay bounded by the admitted training
information range, and stateless/unsupervised models omit the channel
entirely. A model performing its own forward read inside `fit` is a leakage
bug. `TrainingTargetFrame` is generic — named target columns and alignment,
no classification/regression assumption.

**Output → decision chain**
([ADR-0009](../adr/ADR-0009-generic-output-and-intentframe-family.md)):
ResearchModel outputs are generic — probabilities, expected returns,
similarity statistics, distances, regime probabilities, labels, arbitrary
named numerics. **No required trading vocabulary** (banned-keys test).
DecisionPolicy converts a ModelOutputFrame into an IntentFrame; multiple
policies must consume one persisted/cached ModelOutputFrame with zero
re-inference. IntentFrames carry an `intent_schema_id`; V1 ships
`TargetExposureIntentV1` (`target_exposure ∈ [−1,+1]`; `NaN` = abstain/no new
instruction; `0.0` = explicitly flat) — the first concrete schema, not the
permanent definition — and, since 2026-08-22,
`bracketed_exposure_intent_v1`, which adds two float64 channels
(`take_profit_distance`, `stop_loss_distance`, in price units; `NaN` = this
instruction supplies none for that side) so a policy can attach one immutable
bracket to the trade it opens
([ADR-0023](../adr/ADR-0023-phase-4-simulation-contracts.md) Amendment 1).
Further schemas (orders, limits, cancellations, staged entries)
register new ids without touching ResearchModels. Simulators declare
supported schema ids; mismatches fail at resolve time.

**Sparse frames are legal** ([ADR-0009](../adr/ADR-0009-generic-output-and-intentframe-family.md)):
ModelOutputFrame and IntentFrame may be indexed by a strict subset of the
evaluation view's native keys, so event-driven research is first-class and
need not emit millions of abstention rows. **Absence of a row ≠ a dense row
containing `NaN`**: absence means no statement was produced at that key;
`NaN` means explicit abstain, holder keeps prior state. Consumers must
preserve the distinction; ordering and range bounds still apply.

**Two evaluation planes**
([ADR-0010](../adr/ADR-0010-two-plane-evaluation-and-outcomespec.md)):
- **Plane A — forecast evaluation:** ModelOutputFrame + versioned OutcomeSpec.
  No simulator required. Most hypotheses should die here, cheaply.
- **Plane B — trade evaluation:** TradeLog/EquityCurve from the simulator
  ([ADR-0023](../adr/ADR-0023-phase-4-simulation-contracts.md)). The simulator
  is second, never first: it filters an edge Plane A already found, and TP/SL
  or cost tuning may not substitute for establishing predictive edge in Plane A.
  Every money-denominated result carries the cost-semantics evidence status of
  its `ExecutionSpec`'s identified cost binding
  ([ADR-0020](../adr/ADR-0020-cost-semantics-quarantine.md) Amendment 1,
  [COST_AUDIT.md](../research/COST_AUDIT.md)); while that status is
  `unverified`, such results may not be represented as authoritative real-money
  estimates. `verified` is **fail-closed**: it resolves only against a
  repository-controlled binding created when the audit closes, so a config
  cannot self-certify evidence. The simulator's **executable price path** is
  likewise declared rather than assumed — which side of the market the recorded
  OHLC represents is an open audit fact, so V1 runs a *named provisional* price
  model and leaves the side-dependent interpretation of fills and bracket levels
  explicitly unbound
  ([ADR-0023](../adr/ADR-0023-phase-4-simulation-contracts.md) §8). Plane-B evaluation entries carry the DecisionPolicy dimension that
  Plane-A entries deliberately do not (§7).

**OutcomeSpec** is the ONLY component permitted to read forward of *t*. Its
outputs are barred from feature inputs, inference inputs, and DecisionPolicy
inputs (declared-input check + test); the single exception is the fit-time
`TrainingTargetFrame` channel above. It defines horizon, reference price,
decision delay, gap/boundary policy, and alignment rules — versioned like any
plugin — and its declaration is what the fold-boundary purge is derived from.

## 7. Experiment identity and runs

([ADR-0011](../adr/ADR-0011-run-identity-and-canonical-runs.md))

- **experiment_fingerprint** — deterministic hash of all reproducibility
  inputs (resolved config, dataset manifest hashes, plugin ids/versions/
  params/source hashes, Git commit, dependency lock hash, outcome/execution
  spec ids, seed, algorithm version). Machine identity is captured but
  excluded from the fingerprint.
- **run_id** — ULID minted per execution; run-directory name.
- **attempt_number** — count of executions sharing a fingerprint. Running one
  fingerprint twice and comparing artifact hashes is the determinism
  verification ([ADR-0016](../adr/ADR-0016-determinism-tiers.md): exact for
  integer/structural domains; pinned + seeded + documented tolerances for
  float paths; no cross-hardware bitwise claims).

**Canonical runs require:** clean Git tree at a recorded commit, lockfile in
sync, `full` integrity verification, no lockbox access (unless the run is a
declared lockbox-evaluation run, its own audited class). Dirty-tree runs are
permitted only as **noncanonical** with the diff captured/hashed and the flag
visible in the manifest.

**Statistical trial counting (ratified, amended):** a run is **not**
automatically one trial — one run fans out N policies × M OutcomeSpecs × H
horizons. Every run therefore persists an **evaluation inventory** (model/
FittedState, **DecisionPolicy *where a decision plane was evaluated***,
OutcomeSpec, horizon, metric family where material). The policy dimension
enters an entry only when policy output was actually evaluated: a Plane-A
forecast evaluator consumes a ModelOutputFrame and OutcomeSpec targets and never
sees an IntentFrame, so policy fan-out alone does not multiply Plane-A
evaluations. Executed-but-unevaluated work is still recorded in the RunManifest. Every valid evaluated hypothesis is recorded, bad and
disappointing results included. Pure infrastructure failures (syntax error,
environment failure, disk I/O failure, crash before evaluation, platform-bug
contract failure) produced no evaluation and are not statistical
evaluations, but are permanently recorded as failed executions and never
deleted or hidden; a descriptive run that legitimately ends before any
evaluation is likewise recorded and not a statistical evaluation.

**Multiple-testing denominator — resolved (2026-08-15,
[ADR-0024](../adr/ADR-0024-multiple-testing-trial-ledger.md), owner decision
OD-5A).** This was formerly *"a blocking decision before any deflated statistic
ships in Phase 5"* ([ADR-0011](../adr/ADR-0011-run-identity-and-canonical-runs.md)
Amendment 1); it is closed by ADR-0024 and recorded there as ADR-0011
Amendment 4. **One trial is one distinct `(hypothesis, question)` pair that
produced at least one evaluation**, with `hypothesis = experiment_fingerprint`
and the *question* composed from evaluation-inventory dimensions. Plane A and
Plane B are counted separately and never summed; **folds collapse**; attempts
sharing a fingerprint collapse; descriptive runs, pre-evaluation failures and
executed-but-unevaluated policies contribute zero. **Raw run count remains an
invalid denominator.** Correlation between related variants is acknowledged and
**not** estimated — the platform does not persist the inputs an effective-trial
estimate would need — so related variants are counted individually as a
conservative denominator, with no claim of independence. **V1 ships no
deflated, adjusted or multiple-testing-corrected statistic, no p-value, no
significance claim and no effective-independent-trial estimate**; what ships is
the denominator itself with a mandatory caveat (the **Trial Ledger**).

Because the fingerprint includes the Git commit, documentation-only commits
over-segment otherwise identical experiments. This is the safe direction
(never a collision); a future hypothesis/comparison key may group them
without weakening the fingerprint.

**Run states:** PENDING → RUNNING → COMPLETE | FAILED; RUNNING → INTERRUPTED
(graceful self-mark on SIGTERM, or observer-marked on stale heartbeat).
Retries append attempts; a COMPLETE run directory is immutable — supersede,
never mutate.

## 8. Storage ([ADR-0017](../adr/ADR-0017-storage-files-as-truth.md))

Files are the source of truth: Parquet/columnar for bulk artifacts, JSON for
manifests/configs/metrics, run directories for everything a run produced.
SQLite is a **derived, rebuildable index only** — rebuilding it from run
directories is a tested code path. No PostgreSQL in V1. No automatic
deletion; warn at 70 % disk. Pickle is banned as a durable artifact format.

**Phase-5 realization ([ADR-0017](../adr/ADR-0017-storage-files-as-truth.md)
Amendment 1).** The index lives at `<runs_root>/index/` — outside the run
collection, which refuses any entry that is not a run identifier, and outside
the Git working tree. It is **rebuilt through a non-mutating read path**:
rebuilding or deleting it must not modify one byte of research truth, and a
test proves the runs root is byte-identical across a rebuild. Corruption
recovery is rebuild-from-files; database state is never authoritative and never
repaired in place. **The index participates in nothing that matters** — not run
identity, canonicality, gating, audit or any evaluation result — enforced by a
one-way layer dependency rather than by convention.

## 9. Execution ([ADR-0018](../adr/ADR-0018-execution-model.md))

Modular monolith. One experiment = one detached process launched through the
CLI (`systemd-run --user` with linger enabled — verified on this VM — or tmux
fallback). Long-running experiments never depend on an SSH session.
Heartbeats + content-addressed stage caching make re-running an interrupted
experiment reuse completed work. Large intermediates never go to `/tmp`
(RAM-backed on this VM) — see CLAUDE.local.md for the disk-backed TMPDIR.

**Experiment-scale operations ([ADR-0018](../adr/ADR-0018-execution-model.md)
Amendment 1, owner decisions OD-5C and OD-5D).** Scale-out is a **bounded local
process pool over whole runs**: a sweep expands deterministically into complete,
ordinary child runs, each registered and executed through the unchanged
single-run path, and resume derives remaining work from run directories rather
than from any scheduler state. **Folds remain sequential inside each run, and
there is no nested parallelism** — no queue daemon, no remote workers, no
distributed execution. Concurrency is capped by the available CPU and a memory
budget (planning defaults: 8 workers, 1 GiB assumed per-run admission RSS,
16 GiB budget — budgeting constants, not assumptions about every future model).
Workers run under an explicit single-thread clamp environment that every launch
path constructs identically and that the worker verifies fail-closed
([ADR-0016](../adr/ADR-0016-determinism-tiers.md) Amendment 1 — implemented in
Phase 5). The disposable SQLite index is published as one staged,
fsync'd, atomically renamed generation so readers see a complete old or new
inode; no scheduler or index state becomes research truth
([ADR-0017](../adr/ADR-0017-storage-files-as-truth.md) Amendment 2).

## 10. V1 non-goals

No multi-symbol/portfolio/cross-asset infrastructure
([ADR-0015](../adr/ADR-0015-v1-single-symbol-scope.md) — and, per its
Amendment 1, **no `PortfolioPolicy` symbol at all**: with one symbol and one
open trade there is nothing for a pass-through seam to pass through) · no
live/paper trading or broker connectivity · no MT5
integration in this repo · no Kubernetes/microservices/queue daemon/broker ·
no PostgreSQL · no web dashboards/APIs · no distributed compute · no
authoritative real-money claim from simulation before the cost audit closes
([ADR-0020](../adr/ADR-0020-cost-semantics-quarantine.md) Amendment 1) · no
general order engine, partial fills, trailing stops, multiple simultaneous
positions, margin/leverage, slippage model or position-limit framework
([ADR-0023](../adr/ADR-0023-phase-4-simulation-contracts.md)) · no UTC or
cross-domain resolution · no external data feeds · no automatic artifact GC ·
no ANN/vector database infrastructure · no order-type intent schemas, and no
intent-schema registry — a simulator's frozen literal tuple of supported ids is
the whole resolution mechanism · **no deflated, adjusted or
multiple-testing-corrected statistic, p-value, significance claim or
effective-independent-trial estimate**
([ADR-0024](../adr/ADR-0024-multiple-testing-trial-ledger.md)) · **no
fold-level or nested parallelism**
([ADR-0018](../adr/ADR-0018-execution-model.md) Amendment 1) · no
cross-hardware bitwise determinism claims.
